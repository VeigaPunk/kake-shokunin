## 1. Recovered conventions (observed, with evidence)

### A1 — Exit contract
| Code | Meaning | Evidence |
|---|---|---|
| `0` | clean | `scripts/corpus-contract.mjs` header "Exit contract: 0 = clean · 1 = findings · 2 = could-not-evaluate … Exit 2 outranks exit 1 when both apply" |
| `1` | findings / failed policy | `evaluate()`: `const code = errors.length ? 2 : findings.length ? 1 : 0` (read at `corpus-contract.mjs:143-260`) |
| `2` | could-not-evaluate (unreadable/missing inputs, unsupported shape, internal crash) | same line; `main().catch(… process.exit(2))` (file tail) |
| `64` | usage error (unknown flag, missing flag value) | `parseArgs()` returns `{err:64}` → `process.exit(64)`; usage text on stderr carries tool-name prefix `corpus-contract:` |

- **Precedence rule:** exit `2` outranks exit `1` when both apply (stated in header; encoded in the single ternary). This exact map `{0,1,2,64}` is what `SKILL.md` L212 declares for `freshness-sweep` and what the r21 spec/GateContract checklist item 4 required ("declare each in the row; undeclared codes read as could-not-evaluate", PROTOCOL Gate standard).
- Exit contract is **independent of output mode**: selftest case `c3` pins human-mode exit 1 on the failing corpus (`corpus-contract.mjs:504-514` region, case c3).
- r21 lesson "Final measured results" re-verified the map end-to-end: selftest `7/7 passed, exit 0`; `--json` exit 0; replay exit 0; a *deliberately red* baseline run exits 1 (`measure-before.json` receipt).

### A2 — stdout contract
- Default (human) mode: deterministic lines — header line, `root:` line, then one line per finding/skip/error prefixed `FAIL `/`SKIP `/`ERROR `, then a single `result: … — exit C` summary line (`emit()`, `corpus-contract.mjs:219-236`).
- `--json` mode: **exactly one JSON object on stdout**, schema `{tool, contract, root, ok, code, counts, findings, skipped, errors}` with `ok = (code === 0)`. Errors never go to stdout; usage errors and crashes go to stderr with a tool-name prefix.
- **Determinism requirement:** findings/skipped/errors sorted before emit ("Output is deterministic: sorted findings/skips, no timestamps", file header; sort at `corpus-contract.mjs:206-211`). Stable finding ids embed enough context to be unique (`missing_metadata:<file>:<field>`, `missing_gate:<file>`).
- `--help` prints usage to stdout; it is not a findings run (no exit-code finding semantics beyond 0).

### A3 — Selftest contract
Observed in `corpus-contract.mjs` `selftest()` (L≈362-557) and required by r21 `w1/GateContract.md` F6:
1. **Hermetic fixtures** built under `fs.mkdtempSync(os.tmpdir(), 'kake-…')`; every fs write sits inside `// SELFTEST-WRITES-BEGIN/END` markers (only write regions in the file).
2. **Subprocess invocation of the CLI itself** (`execFileSync(process.execPath, [SELF, …args])`) in read-only `--root/--json` mode — "helper-only self-check does not satisfy" (GateContract F6 quoting PROTOCOL self-test standard). Children never write.
3. **Pinned literal expectations** (`EXPECTED_CLEAN`, `EXPECTED_FAIL`, `EXPECTED_BARE` constants) compared byte-for-byte via `JSON.stringify`; literals are not generated by the function under test.
4. **Both polarities + adversarial fixtures**: clean corpus with exclusion cases; failing corpus with reviewer-driven negative (`bare-then-key.md` — a bare `source:` label must not absorb the next line's key); line-window boundary (trio on line 9 fails); fence-aware/wrong-level heading negatives; exclusion-name positives.
5. **Case table output**: `PASS/FAIL  <id>` with `expect:`/`got:` lines, then `selftest: N/N passed`. Exit: `0` all pass · `1` any fail · `2` selftest itself cannot run.
6. **Usage/absent-input cases inside the battery**: c5 absent root → exit 2, errors populated, no findings; c6 unknown flag / bare `--root` / empty `--root=` → all exit 64.
7. **Write-confinement proof**: static self-source scan `writeConfinement()` (covers ~30 write-API spellings; residual bypasses enumerated in-source) **plus** synthetic positive/negative controls for the scanner itself (case e1). The registry row records honestly that this is "not a complete write-free proof"; r20 resume hardened the scanner to 25/25 mutant-kill (`SKILL.md` L212 bracket note; `confinement-mutants.mjs`). GateContract **F7** rules the *sufficient* proof is runtime: digest the tree before/after normal run and selftest, assert no change outside the temp root.
8. **Isolation convention**: caller isolates `HOME`/`TMPDIR` (`KAKE_SELFTEST_DIR` for freshness-sweep) to temp dirs; *record variable names only, never values*.

### A4 — Frozen-proof / revision-binding contract
Observed artifacts: `.ufo/waves/round-21/frozen/before/expected.json`, `.ufo/waves/round-21/replay-proof.mjs`, `.ufo/waves/round-21/measure.mjs`, r21 lesson "Final measured results".
- `expected.json` schema: `revision` (full sha) · `name` · `argv` (exact gate command) · `expected_finding_ids` (stable id families) · `inputs` {relpath → sha256} covering **every** frozen input (36 files) · counts · `expected_exit`. GateContract F4: counts alone are insufficient — the baseline must pin argv, gate-script SHA-256, and the findings/ID list too.
- **Replay proof order** (replay-proof.mjs header, "Proof order"):
  1. verify EVERY input digest **before any execution** — any mismatch ⇒ `snapshot_tampered`, exit 2, gate never run;
  2. run the gate **twice** on the unchanged snapshot — exit must equal `expected_exit` and both runs' stdout must be **byte-identical** (no ordering drift);
  3. extract stable finding ids from raw stdout and check per-file/per-lesson counts against expected counts;
  4. **re-verify every input digest after execution** — the gate is read-only and the replay must not mutate the snapshot either.
  Replay exit: `0` PASS · `1` FAIL (contract assertion) · `2` could-not-evaluate/`snapshot_tampered`. Unpinned legacy baseline (no `inputs`) maps to could-not-evaluate (GateContract F5/F6; lane decision recorded in the registry row).
- **Revision binding** (GateContract F2; measure.mjs): a verdict names the revision it measured; `--revision <sha>` reads `git ls-tree`/`git show` blobs (argv-form, no shell, no writes) instead of trusting a moving worktree. r21 receipts: `measure-before.json` / `measure-after.json` carry exact argv, full outputs, exits; lesson records measured commit `df6196b` vs baseline `5009ecaa`.
- **Honest absence** principle (r21 lesson C2): missing evidence stays missing — "baseline absence yields accepted=0, not pretending behavior ran" is the same rule the r22 Matrix/Measure prompts restate.
- Frozen location convention: `.ufo/waves/round-<N>/frozen/before/`, referenced by explicit name (F9: bare `before` is fragile).

### Contract gaps / L1 decisions surfaced by the mapping (not findings against any seat; contract is frozen and authoritative)
1. **Precedence 2>1 is not stated in `contract.json`.** r21 convention says could-not-evaluate outranks findings; recommend `canonical_audit.py` implements it and selftest pins a combined case (unreadable input + mismatching canonical on another page → exit 2).
2. **stdout shape in non-`--json` mode**: contract's `outputs.stdout` describes the JSON object; CLI advertises `[--json]`. Safe reading: `--json` emits the contract JSON object; default mode may emit human lines but must preserve the exit map and determinism. L1 should bless one reading so Matrix's byte-comparison expectations are stable (Matrix invokes with `--json`, so the JSON path is the contractual one).
3. **`verdict` value vocabulary** (e.g. `clean | failed | could_not_evaluate`) is not enumerated in the contract — derive from `exitMap` labels; declare it in the registry row (GateContract F6/F8 honesty: label what the check does *not* do — no freshness, no search-engine selection, no publishing readiness).
4. **`pagesChecked` semantics**: pages attempted vs pages successfully evaluated is undecided; given exit-2 cases are could-not-evaluate, recommend "attempted", with per-page status visible in findings/errors — L1 call.
5. r22 has no `frozen/before/expected.json`; its replacement (revision-blob materialization + `cases.json` pins) is *stronger* than r21's tree-snapshot digest map — but the run-twice byte-identical determinism proof from replay-proof.mjs has no named owner in the three executor prompts; recommend L1 assigns it (Matrix double-run or Measure repeat) so the proof is not orphaned.
