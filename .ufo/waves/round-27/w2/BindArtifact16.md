## 3. Findings

**F1 — MEDIUM (gate weakness, not a defect of the S023 record): the artifact branch does not assert row identity, so a mis-bound artifact record is undetectable.**
The counter validates an artifact record with `p['contains'] not in blob(p['evidence']).decode()` — plain containment over the whole file. I replayed that exact branch with the S023 record's `contains` replaced by **S022's registry row text**: errors `[]` → the check **passes**. The check therefore cannot distinguish "bound to the S023 row" from "bound to some other row of the same file". S023's own committed binding is correct (P2), so no false PASS occurred here, but the same weakness applies to every artifact record in this wave (`S004`, `S006`, `S022`, `S023` all bind `corpus/SOURCES.md` rows). No live edit made (this wave is read-only); the fix is a locator assertion (bound substring must lie inside the row whose id equals `row`), which the contract's `artifact` shape (`evidence repo path, contains substring`) does not currently demand.

**F2 — LOW/MEDIUM (disclosure completeness of the committed reason): the bound substring stops exactly one cell before the only cell that contradicts reading this as a citation, and the reason says "The registry … records agree" without saying which cell agrees.**
The S023 row's `used-by` cell is `corpus/lessons/round-22.md` — it does **not** list `corpus/knowledge/static-canonical-preflight.md`. The bound `contains` ends at `| 90d |`, i.e. before that cell, so the artifact as bound cannot show it. The reason's "the registry and historical lesson records agree" is true about the **date** (registry `opened 2026-10-20`; lesson round-22 heading `:36`; anchor "accessed 2026-10-20") but is not true of the registry's `used-by` attribution for this file — and the reason does not say that the registry excludes the citing file. Independently confirmed as the correct reading of the relationship: at base the citing file contained **zero** literal `S023` tokens (the pair exists only via the line-2 range `S020-S027`), the file's own `source:` header lists only S020/S021/S026/S027/S028/S029, and `corpus/lessons/round-22.md:55` states "C1's knowledge entry cites S020/S021/S026/S027; the remaining rows ground its implementation/rejection boundaries". The sibling artifact record for `S022` has the identical truncation and identical reason text → systemic, not a one-off. Both W1 reviews that produced this record already disclosed the `used-by` discrepancy (`.ufo/waves/round-27/w1/Pair16A.md` §5 "Registry cross-check"; `Pair16B.md` §4) — the **committed ledger reason drops that disclosure**, so a reader of the ledger alone can over-read the registry as attributing this file to S023. Recommended append-only disclosure in the reason or the citing file: name that the registry's `used-by` for S022/S023 excludes this file and that the mention is a verification-date stamp only.
