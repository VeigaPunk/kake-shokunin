## Generation finding: hand-authored static HTML, tags retrofitted by one-off bulk commits — no template

- Not generated at deploy: `.github/workflows/pages.yml` only validates agent payloads, tests the Kimi
  marketplace builder, runs `cargo test` for the validator, then `actions/upload-pages-artifact@v3` with
  `path: ./ds4cc-marketplace`. No HTML build step; `deploy-github-pages.sh` is a DNS/instructions script.
- No template/partial machinery: a tree-wide search for head/layout/include/partial/template files finds
  none outside `marketplace/plugins/**` (unrelated plugin packs). `git grep -li 'og:title'` over every
  non-`.html` tracked file returns **zero paths**, so nothing in `scripts/` (`build-ds4cc-submission.py`,
  `build-kimi-marketplace.py`, …) emits og tags. No `Generated by` / `DO NOT EDIT` markers in any page.
- Provenance is a bulk edit: `e38da85` (2026-09-26) "magga: canonical+og+description head metadata on 73
  pages … per frozen r03 template" adds the identical 5–6 line head block to 73 static files; `96dca57`
  (same day) adds canonical+og:url to `index.html` and the speedrun artifact; `f2431d2` adds infinizoom head
  meta. Later magga pages ship og from birth by copying the pattern (`magga/frostbite/index.html` at 7fc6aa2f
  has the full block, lines 8–12). Result: a uniform hand-maintained block in 87 heads, and the burnerchrome
  family plus three older root pages were simply never touched.
- Page families differ structurally (`index.html` inlines CSS with an unindented head; `burnerchrome/*`
  uses an indented head + shared `assets/styles.css`, 11/11 pages), confirming per-page hand editing rather
  than one generator.

## Where a source fix would go

1. Missing og for the 11 Musketeer pages: each file's own `<head>` at `burnerchrome/*.html` and
   `burnerchrome/adapters/*.html` (uniform indented head, `<title>` on line 6, canonical on line 9 — one edit
   template fits all 11). `burnerchrome/README.md:19` shows the family is also mirrored at
   `burnerchrome.vercel.app` and commit 3586cf7 calls the vendored copy "the maintained canonical line", so
   the same block must also land in whatever publishes the mirror, or the two diverge again.
2. `bloat.html`, `exa.html`, `benchmarks/benxshitter-frontier.html`: their own heads (root style, inline CSS).
   `burnerchrome.html` needs nothing until its target gains tags, since it is a 0-second redirect shim.
3. Missing `og:image` on the other 86: no site-default social image exists — `assets/` at repo root contains
   only the five JetBrainsMono woff2 fonts and there is no root-level png/jpg/webp/ico in the tree
   (`git ls-tree --name-only 7fc6aa2f | grep -Ei '\.(png|jpg|jpeg|webp|svg|ico)$'` → empty, exit 1). A fix
   needs a new 1200×630 raster asset (SVG is not reliably read by previews) plus one `og:image` line per
   head, absolute URL like the omegag example. With no template in-tree, that is 100 hand edits or a new
   generator step — the absence of a generator is the real structural gap, not the 15 pages.
