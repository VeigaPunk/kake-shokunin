## Contradictions / divergences with C1 contract sentences (concrete input → two outcomes)
- **D1 (e), the serious one.** 2.2.2: "those in the reserved range defined by [ RFC3986 ] , MUST be percent-encoded as defined by [ RFC3986 ] prior to comparison". Literal MUST: `%2F` and `/` encode to the same octets, i.e. they are **equal**. Contract (e): "reserved characters are never decoded or encoded, so `%2F` and `/` differ". Input `disallow: /a%2Fb`, url `/a/b` → RFC-MUST blocks, contract allows. The RFC's own Figure 4 row 1 leaves `/` and `?` literal, contradicting its sentence; the contract's reading follows the figure and the second sentence, **not** the MUST. Known-wrong either way: the lane reading must be visibly tagged as overriding a MUST.
- **D2 (c).** 2.1: "The group is terminated by a user-agent line or end of file." Input `user-agent: A` / `user-agent: B` / `disallow: /x`, check A on `/x`: contract = one group {A,B} → blocked; 2.1 + Figure 2 + 2.1 "The last group may have no rules, which means it implicitly allows everything." → A's group has no rules → allowed. The ABNF comment (quote 10) backs the contract, 2.1's prose does not. RFC self-conflict on an ordinary file; contract picks one side silently.
- **D3 (d).** "most octets" is ambiguous between rule length and matched span. `allow: /a*` + `disallow: /abc`, path `/abcdef`: contract (rule value, `*` counted) → /abc wins → blocked; matched-span reading → `/a*` spans 7 → allowed. Counting `$` as an octet is unbasisable in the RFC: `allow: /x$` vs `disallow: /xy` (both 3) → allow; excluding the anchor (2 vs 3) → disallow.
- **D4 (d).** "equivalent" widened to "of that length": `allow: /a*` + `disallow: /ab`, path `/ab` → contract allows; the RFC's SHOULD covers only equivalent rules, and its specificity rule ties at 3 octets, leaving the outcome unspecified. A SHOULD stretched past its antecedent.
- **D5 (f).** 2.2: `product-token = identifier / "*"` admits `*` as a product token, so `userAgent: "*"` is a legal crawler name; the contract's token (2.2.1 prose only) excludes it → `check_invalid` → `could-not-evaluate`. Yet (c) must honour `*` as a group name. The RFC's two definitions conflict; the contract cites 2.2.1 and says nothing about the ABNF alternative.
- **D6 (e).** Contract ties the implicit allow to a path **equal** to `/robots.txt`, but the path to match carries the query, so `disallow: /` blocks `https://h/robots.txt?x=1`. RFC: "The /robots.txt URI is implicitly allowed." — a URI includes its query, so the literal sentence allows it. Narrow, unmarked.
- **D7 (b).** BOM drop. `EF BB BF` is not in `WS` and not part of the literal `"user-agent"`, so grammar-literal parsing makes a BOM-prefixed first line unparseable → no group → allowed; the contract drops it → `user-agent: *` becomes a group. Input BOM + `user-agent: *` + `disallow: /x`, url `/x` → contract blocked, grammar-literal allowed. 2.3.1.5 "Crawlers MUST try to parse each line of the robots.txt file." only weakly supports leniency; 2.3 says "The file MUST be UTF-8 encoded" and never mentions a BOM.
- **D8 (b) + declaration.** Invalid UTF-8 → U+FFFD keeps a **live** rule: `path-pattern = "/" *UTF8-char-noctl` with `UTF8-1-noctl … ; excluding control, space, "#"` admits only valid UTF-8, so an invalid byte makes the line unparseable/ignored; under the contract it becomes `%EF%BF%BD` and can block. 2.2.2 "Implementors MAY bridge encoding mismatches" is neither substituting nor ignoring.
- **D9 (a)/(f).** 2.3.1.2: "The crawlers SHOULD follow at least five consecutive redirects, even across authorities" and a file reached within five redirects MUST be "fetched, parsed, and its rules followed". The contract's status ranges exclude 3xx, so a 301/302 `/robots.txt` is `check_invalid` → `could-not-evaluate`: an RFC-sanctioned publisher cannot be audited at all. The C1 limits declare "does not … follow redirects", not that such a host is un-auditable.
- **D10 (declaration, checkable).** C1 limits: "Where RFC 9309 says SHOULD or MAY, the contract fixes one reading (marked "lane reading")". The C1 block at `4b089da` marks exactly **two** ((b) "lane reading: exactly this limit"; (e) "Lane reading of the section 2.2.2 examples"). Unmarked fixings of a SHOULD/MAY: (a) 400–499 "allowed" (MAY); (b) orphan rules "ignored" (SHOULD); (d) allow-wins for equal-length non-equivalent rules (SHOULD, narrower); (e) `/robots.txt` allow narrowed to file-decides (RFC states it unconditionally). Either mark them or weaken the sentence.
