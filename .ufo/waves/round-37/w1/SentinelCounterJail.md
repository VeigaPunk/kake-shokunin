# Round 37 counter jail review — SentinelCounterJail

Axes: operability and freshness. Scope: jail visibility, shared-state contamination, and materialization. No remediation edits made.

## Verdict
- **High — C1 measurement integrity:** the candidate tool and case data share one read-write scratch mount across invocations. A tool can persist state and replace the tool file that later cases execute. The reported `toolSha256` remains the original in-memory bytes, not a hash of the file later executed.
- **Medium — C2 measurement integrity:** fixture runs share a read-write mount containing all tool files and live fixture boxes; one run can read/replace another tool and writes outside its own `work` snapshot are not detected.
- **Medium — C2 imported selftest:** import-time selftest code can write persistent scratch state consumed by later fixture runs.
- **No sealed-key or lane exposure observed:** jail root contains `/usr`, `/proc`, `/dev`, private `/tmp`, and the bound scratch path; `/home` is absent and the lane path check returned false. I did not list, read, stat, search, or open the sealed-key tree; no real key was used.
