## Behavior changes outside the attribute case (`repro.py` → `out/repro.txt`; WHATWG oracle `oracle.py` → `out/oracle.txt`)
Each reproducer is one text/html body. Results are given as old verdict / new verdict / what the html5lib oracle says.
- **R1 (regression, false hold).** Body `<img alt=it's>VISIBLE<script>secret()</script><p>END</p>`, quote `secret()`. Old: failed-policy, exit 1. New: clean, exit 0. Oracle: there is one script element and `secret()` is its raw text, so old is right. Cause: `tag_end` (`scripts/source_recheck.py:288-303`) treats any `'` or `"` inside a tag as the start of a quoted value. Here the stray `'` never closes, `tag_end` returns -1, and `remove_raw_elements` appends the rest of the document unprocessed (`:360-363`). From that point on, no script, style or template element is removed.
- **R1b, R2, R2b, R7 (same class, all false holds; oracle agrees with old).**
  - R1b: `<img alt=it's><script>secret()</script><p>it's END</p>`
  - R2: `<div x"y>A</div><script>secret()</script>`
  - R2b: `<a b='c'd'>A</a><style>secret{}</style>`
  - R7: `<p>if a<b it's</p><script>secret()</script>…`
- **R4b (regression, false missing).** Body `<style>x</style '>VISIBLE AFTER`. The quote-aware close of the end tag (`:373-375`) finds no `>` and drops the whole remainder. Old: clean. New: failed-policy. Oracle: `VISIBLE AFTER` is visible, so old is right.
- **R3 (fix, not described anywhere).** Body `<script data-x="</script>">HIDDEN</script>VISIBLE`. Old shows `">HIDDEN`; new removes it. Oracle agrees with new. This is the raw element's own start tag, not "another tag's attribute value".
- **R4 (fix, not described).** Body `<script>x</script a='>'>VISIBLE`. Old shows `'>VISIBLE`; new shows `VISIBLE`. Oracle agrees with new.
- **R5 (fix, not described).** Body `<ſcript>HIDDEN</script>VISIBLE` (U+017F long s). The old tool crashes with an uncaught `KeyError: 'ſcript'` from `re.IGNORECASE` Unicode folding, exit 1, no JSON report. The new tool returns clean. Oracle: there is no script element, so new is right. The end-tag regexes still use `re.IGNORECASE` (`:283-286`), so `</ſcript>` still closes an element, which breaks contract (c)'s "ASCII case-insensitive". This is pre-existing and unchanged.
- **R6.** Body `<script a='>x</script>VISIBLE`. Old shows `VISIBLE`; new shows `xVISIBLE`. The oracle shows no text at all, so neither version matches.
- **Speed.** On a 16 MB synthetic body, old takes 0.16 s and new 1.03 s; on the 237 real bodies, 0.33 s versus 1.76 s. Runtime stays linear and I found no quadratic input.

## Manifest, body-open and g32 probes (`probe.sh`)
- **"MemoryError is caught": overstated.** It is caught only around `handle.read` (`:638-641`). A 62,914,584-byte regular manifest of `{}` objects (under the 64 MiB cap) run under `ulimit -v 524288`, the same 512 MiB limit g30 uses, raises `MemoryError` inside `json.loads` (`:649`). The result is exit 1, a traceback, and no report, for both old and new. The code comment at `:37-40` ("never becomes a MemoryError with no report") is therefore false.
- **Manifest from a pipe or process substitution is newly refused.** `echo '{"version":1,"checks":[]}' | … --manifest /dev/stdin`: old exits 0 with clean; new exits 2 with `input_invalid`. The lesson counts this as "unreadable", but SCORECARD's round-36 contract (g) text has no "non-regular" or "64 MiB" sentence. The behavior change is real but has no contract wording.
- **"No check-then-open race re-resolves a symlink": overstated.** `body_path` runs twice, in `validate_check` (`:539`) and `evaluate_check` (`:583`), and the body is then opened with a plain `open(real)` (`:585`). I simulated the race in-process: after validation, `body.html` was replaced by a symlink to `../outside.html`, and the tool read the outside file (`findings: []`, the outside quote held). Returning the realpath narrows the window (retargeting the original symlink no longer works) but does not close it. If `body_path` returns None on the second call, `open(None)` raises `TypeError`. That is pre-existing.
- **Is g32 robust without strace?** It fails closed but is host-dependent:
  - No strace on PATH: the selftest exits 1 with "strace is not available"; g32 does not silently pass.
  - Failing strace (simulated ptrace denial): exits 1 with an exit-mismatch message.
  - Strace that writes an empty trace: exits 1 with "did not open".
  - **False red on a correct tool:** with `TMPDIR` reached through a symlink, the correct tool fails g32 with `opened: ['manifest.json']` (exit 1). The tool opens the realpath, but `check_open_paths` matches only the unresolved `case_dir` prefix (selftest `:340-356`). Hosts where `/tmp` is a symlink, such as macOS's `/private/tmp`, would hit this.
  - So "green on the fix" holds only on Linux with working ptrace and a TMPDIR whose path contains no symlinks. Two possible repairs: resolve `case_dir` before matching, or add an strace-free check that calls `body_path` in-process and asserts it returns the realpath.

## Verdicts
- "a raw-element start tag counts only where a tag can start" as implemented: **wrong** beyond the attribute case. R1, R1b, R2, R2b, R7 and R4b contradict round-36 (c), "contents of script, style and template elements removed" (`SCORECARD.md:1623-1628`), and the sentence's own wording, because per S092 a tag *can* start at each of those `<script` and `<style>` tags.
- Amendment wording: **overstated and under-specified.** It defines neither what an attribute value is nor where a tag ends. It does not cover the R3, R4 or R5 changes. It was never written into the round-36 contract text in SCORECARD. And `strip_tags` still ends a tag at "the next `>`", so the two halves of bullet (c) now use different definitions of a tag. A suggested wording: "Within a tag, a value that starts with `"` or `'` right after `=` (optional ASCII whitespace) runs to the same quote; a tag ends at the first `>` outside such a value; a raw element runs from the end of its start tag to the next end tag of the same name."

- "round-36 sealed counter 28 of 28 on the fixed tool": **holds** in `--tool-file` mode only. With `--revision 528a6d02` it exits 2. The counter is also not discriminating here, since the old tool scores 28/28 too.
- "Six fixtures … red on 4d5b3d55, green on the fix": **holds**, with g32 green only under the host conditions above.
- "Carried: … fixture g32 needs strace": **holds but understated.** It also needs a TMPDIR path free of symlinks and working ptrace.
