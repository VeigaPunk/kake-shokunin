## Doubts: reproducer, observed output, verdict
- **D1, high: the tool can hang (harmful to operability).** The `*` matcher compiles a backtracking regex: `re.escape(...).replace("\\*", ".*")` at lines 280-288, then `match`/`fullmatch`. Its running time grows like (path length)^(number of stars). Function timings (`decide`, path of 200 `a` characters, rule `/` + `*a`×k + `*b`): k=3 0.03 s, k=4 1.15 s, k=5 35.66 s; k=6 did not finish in the ~264 s left of a 300 s budget. Command-line runs in `cases/M04-*`: k=8 with 200 characters and k=12 with 400 characters each hit the 120 s timeout with no report; k=20 with 2000 characters was still running when I killed it (exit -15). The plausible rule `/*/*/*/*/*/*.pdf$` on a 246-character path took 4.17 s. Command-line reproducer: `dos/r.txt` (44 bytes, rule `/*/*/*/*/*/*/*.pdf$`) and `dos/m.json` (442 bytes, path of 150 segments): `timeout 30 python3 -B clone/scripts/robots_audit.py --manifest dos/m.json` exited 124 with no report. The independent implementation also exited 124 under `timeout 20`. The contract promises one report per run and fixes no time bound, but a publisher-supplied file of a few dozen bytes stops the audit. The independent implementation builds the same regex (`independent_robots_audit.py:106`), so the agreement between the two implementations gives no evidence here. Neither the sealed cases nor the selftest contain a multi-star rule on a long path (none of my searches of the revealed key matched).
- **D2, medium: wrong against (g) "not JSON".** `json.loads` (line 384) accepts `NaN`, `Infinity` and `-Infinity`, which are not JSON under RFC 8259. M01 `{"version":1,"checks":[],"x":NaN}` gives exit 0, `clean`; the contract requires exit 2, `input_invalid`. M02 `"robotsStatus":Infinity` gives `check_invalid` for check `a` where the contract requires `input_invalid`. The independent implementation does the same.
- **D3, low: wrong against (f).** A valid JSON integer of 5000 digits exceeds Python's 4300-digit limit, raises ValueError and is caught at line 385. M03 (`robotsStatus` 9×5000) gives `input_invalid`; the contract requires `check_invalid` because the status is out of range. M03b (the integer in an unused field) gives `input_invalid`; the contract requires `clean`. The independent implementation does the same.
- **D4, low: wrong against "url (absolute URL…)".** `urlsplit` (line 431) silently drops tabs and newlines anywhere in the URL and strips leading spaces and control characters. M09 accepts `ht\ttp://h/a` and ` http://h/a` as valid http URLs. It evaluates `http://h/a\nb` as path `/ab` (rule `Disallow: /ab` decides), although that string is not an RFC 3986 URL. Exit 0, `clean`, 4 checks evaluated. The independent implementation does the same.
- **D5, unverifiable (contract under-specified).** The implicit `/robots.txt` allow compares the raw path (lines 517-518; reading disclosed in the docstring at lines 46-50). With `Disallow: /`, M06 gives `pct` (`/robots%2Etxt`) and `qry` (`/robots.txt?x=1`) `blocked`, while `raw` and `frag` are allowed. Contract (e) says both sides are normalized "before comparison", which can be read to cover this comparison too. The sealed key has no such case (0 occurrences of `robots%2E` or `robots.txt?`).
- **D6, unverifiable (disclosed reading).** "Manifest's directory" is taken as the directory of the symlink's target (line 461). In M07, `r.txt` sits beside a manifest symlink but not beside its target, and the result is `check_invalid`.
- **D7, unverifiable.** Invalid UTF-8 becomes one U+FFFD per maximal subpart (Python `replace`, line 171), not one per byte. In M05, with rule `/a\xE2\x82$`, check `one` (`/a%EF%BF%BD`) is `blocked` and check `two` (two escaped U+FFFD) is allowed. "Invalid bytes becoming U+FFFD" supports either reading, and lesson round-37 "Carried open" already calls this sentence unsourced.
- **D8, unverifiable (contract silent).** A regular robots file that cannot be read (mode 000, M10) gives `check_invalid` (lines 512-514), a fault the (f) list does not name. The docstring discloses it, and `checksEvaluated` is consistent at 1.
- **D9, unverifiable (disclosed reading).** A manifest with a BOM gives `input_invalid` (M08). RFC 8259 allows a parser to ignore the BOM; the contract says only "UTF-8 JSON".
- Held on every check (no defect): M11 (ties and literal `$`), M12 (backslash before `*`), M13 (group continuation across sitemap, no-colon, comment and blank lines; CR-only lines; BOM), M14 (`.`, a directory, a FIFO, a symlink escaping the directory, an absolute path, a NUL, a number → `check_invalid`; `nosuch/../r.txt` and ignored-for-404 are valid), M15 (true, 200.0, 199, 300, 600, `*`, `bot1`, no host, ftp, non-object, empty id, duplicate after an invalid check, `Allow`), M16 and M16b (cut at exactly 512000 bytes), M17, M19 (exactly 64 MiB accepted, 64 MiB + 1 rejected), M20 (only space and tab are trimmed), M21.
