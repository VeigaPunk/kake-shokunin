# PopulationDenominator — C1 attack report (wave 1, critic, read-only)

Seat: `KakeR22.PopulationDenominator` · Claim: **C1 operability capability —
offline static canonical publishing preflight** · Contract:
`.ufo/waves/round-22/contract.json` @ base `7c61c8c`. Attack surface assigned:
**the population denominator** — what "every frozen matrix case" means, whether
the counted set is the frozen 32-name `matrixCases` list or a self-selected
population, and whether the per-case expected oracle is independently authored
or self-graded by the validator under test.

Axes named (godspeed): **correctness** (counted set ≡ frozen set, exact
outcome match), **verifiability** (a non-author can re-derive the denominator
and oracle without running author code), **honesty** (heterogeneous cases not
laundered into a uniform green; out-of-limits claims rejected).

  population** (1/15→15/15) pinned by an explicit baseline list in
  `initial.json`, with "current population 16/16" reported *separately*. That
  precedent is the model here: the denominator must be a named, enumerated

- `corpus/lessons/round-21-verifier-spotcheck.md` — non-author re-measurement

  revision, and the oracle must be checkable without trusting the validator.
- `contract.json` — 32 `matrixCases`, 10 `findingIds`, exitMap

- Probed Python stdlib (`urllib.parse.urljoin`, `html.parser.HTMLParser`) to
  re-derive ambiguous expected cells — evidence below.

## Falsifiable acceptance constraints (all testable, all rejectable)

D1. **Frozen-set provenance.** The case population is exactly the 32 names in
`contract.json matrixCases`, compared as a *set-equality on names*, never a
count, never a filesystem glob of fixture files, never rows the checker
happened to emit. Implementation's case registry minus frozen set must be
reported (extra cases are permitted only as a separately-labelled non-frozen
section; the frozen intersection must show 32 rows, each name exactly once).

D2. **Revision-pinned enumeration.** `python3 .ufo/waves/round-22/measure.py
--root . --revision <sha>` must derive the case population and expected
outcomes from the committed tree at `<sha>` (or from `contract.json` at that
sha) — not from `os.listdir`/`glob` of the live working tree. Otherwise
`--revision` is decorative and a dirty tree silently inflates or deflates the
denominator. Test: checkout base, dirty the fixture dir, run measure at the
measured sha → identical 32-row result or loud failure.

D3. **Oracle is data, not output.** Expected `(exit, findingId)` per case must
live in a checked-in expectation table authored against the contract policy,
*not* generated by `canonical_audit.py` and not diffed against validator
output at measure time. Test: hand-flip one expected value in the oracle →
measure must flag that case; if the suite stays green, the oracle is
self-grading and the claim is unproven.

D4. **Exact-match outcomes.** Per case: observed exit ∈ {0,1,2,64} equals
expected exit, and observed finding-id set equals expected set (subset
containment is not enough — a stray extra `input_invalid` or second finding
fails the case). A validator that emits some finding on everything still
"classifies" every case while being wrong on all 32.

D5. **Positive controls are named and all-green.** The intended-clean subset —
`absolute_match, relative_same_dir, relative_parent, root_relative,
scheme_relative, first_base, second_base_ignored, rel_token_list,
rel_uppercase, attr_uppercase, entity_href, query_preserved` (~12) — must each
exit 0 with `findings: []`. "Proves clean positive controls" is not satisfied
by an unspecified nonzero number of unnamed passes.

D6. **Heterogeneous tail actually runs.** `manifest_traversal` and
`symlink_html` are input-rejection cases (expected exit 2, `input_invalid`),
not HTML-policy pages. They must be instantiated as real executions (a real
traversal path in a manifest; a real symlinked HTML file — `os.path.islink`
check or equivalent), producing real exit-2 rows in the matrix output. A
design-note row, a skipped row, or a case that exists only as a manifest
`file:` string no validator ever opened counts as *missing*.

D7. **Unit of population = case.** 32 rows regardless of how many manifest
pages, fixture files, or emitted findings the implementation uses. The
per-case stdout row must name case, observed exit, observed finding id(s) —
an aggregate "32 passed" with no name-level table is unverifiable and fails
D1.

D8. **No silent carrier for `html_unsupported`.** The findingIds list has 10
ids; the matrix exercises at most ~9. Report may not claim "all finding ids
covered" unless a row actually produces it; unused ids stay unused and said
so.

## Ambiguous oracle cells — must be pinned *before* measuring (self-grading trap)

The contract supplies case **names + policy prose**, not an outcome table. I
re-derived the contentious cells; each has two defensible answers, which is
exactly where a self-authored oracle picks whichever the implementation does:

| Case | Probe evidence | Ambiguity to pin |
|---|---|---|
| `href_empty` | `urljoin('https://example.test/project/a.html','')` → doc URL. Empty href is a valid resolvable reference per RFC/WHATWG; policy rejects only fragments/credentials. | Clean (if `expectedCanonical` == doc URL) vs `canonical_mismatch` vs `canonical_url_invalid`. All three defensible — fixture + oracle must commit and show the rationale. |
| `missing_head` | `HTMLParser` does not synthesize head/body; a link outside `<head>` still surfaces as a starttag. | `canonical_outside_head` (link present, no head element) vs `canonical_missing` (no head, no link) vs `html_unsupported`. Depends on fixture shape the contract does not pin. |
| `base_invalid` | `urlparse`/`urljoin` raise only on some inputs (`http://[::1` raises `Invalid IPv6 URL`; `'a b.html'` resolves happily). | `base_url_invalid` as finding → exit 1 vs could-not-evaluate → exit 2. Both readable off exitMap; pin exit. |
| `invalid_url` | `'a b.html'` silently resolves; WHATWG would percent-encode rather than fail. Fixture must use a URL that is invalid under the stated "WHATWG-like" normalization (e.g., bad IPv6, credentials-bearing — but credentials are separately rejected). | Which exact string, and which id: `canonical_url_invalid` vs `canonical_mismatch`. |
| `scheme_relative` | `urljoin(base,'//example.test/project/a.html')` → `https://…`; positive **iff** fixture `expectedCanonical` is https with same host/path. | Positive vs `wrong_host`/`canonical_mismatch` is fixture-determined. |
| `duplicate_same` | — | Policy says "exactly one" → `canonical_multiple` even when the two hrefs are byte-identical. An implementer may argue dedup; the oracle must pin `canonical_multiple`. |
| `script_decoy` / `comment_decoy` | `HTMLParser` suppresses both natively (probe: no starttag emitted). | The *expected* result is `canonical_missing` — trivially satisfied, so these cases add little unless the fixture also plants a real canonical to prove decoys don't corrupt the count. |
| `template_decoy` | **`HTMLParser` does NOT scope `<template>`** — probe emitted `link [('rel','canonical'),('href','t')]` as a real starttag inside the template. | Validator must track template depth itself; expected `canonical_missing`. This is the one decoy that actually bites stdlib users — if the fixture is dropped or watered down, the matrix's hardest parser case silently vanishes from the denominator. |

## Overclaim to reject (each independently sufficient to reject the claim row)

- "32/32" or "every frozen case" where the denominator was a `glob` of
  fixture files or the checker's own emitted rows rather than the contract's
  name list. Same for "all cases classified" with no name-level table.
- "Validator proven correct" / "validated" — a self-authored oracle proves
  *consistency with the author's own expectations*, not correctness against
  the contract policy. Correct wording: "conforms to the committed frozen
  expectation table."
- Any claim of full `findingIds` coverage (D8), "exhaustive URL policy", or
  WHATWG conformance — contract says "WHATWG-**like**"; `urllib.parse` is not
  a WHATWG URL parser (tabs/newlines/space handling differ).
- Google/canonical-selection or publishing-readiness language — both are in
  the contract `limits` exclusion.
- Counting `manifest_traversal`/`symlink_html` as covered on the strength of
  unit-level path checks that never executed as matrix runs (D6).
- Treating a clean measure run as admission — contract: L1 holds planner, no
  independent admission by author seats.

## Distinct wave-2 attack: denominator drift + self-grading oracle

Siblings own traversal/symlink/normalization/head/parser/stdio/writes
surfaces; this seat owns **who counted the population and who wrote the
answer key**. Concrete wave-2 probes, all cheap:

1. **Name-set diff.** `jq -r .matrixCases[] contract.json | sort` vs the
   implementation's emitted case names → must be identical sets.
2. **Fixture-deletion mutation.** In a clone, delete the `symlink_html`
   fixture and the `manifest_traversal` manifest → measure must exit non-zero
   naming the missing cases. Green after deletion = glob-derived denominator
   = claim dead.
3. **Oracle-flip mutation.** Invert one expected exit in the expectation
   table → that case must fail. Green after flip = oracle is read from
   validator output = self-grading = claim unproven.
4. **Live-tree poisoning.** Commit measured sha, then add a 33rd fixture to
   the dirty working tree → `measure.py --revision <sha>` must still emit 32
   frozen rows (or fail), never 33.
5. **Ambiguous-cell re-derivation.** Re-run the five pinned cells in the
   table above independently (`urljoin`/`HTMLParser` probes suffice) and
   confirm the oracle's chosen answer is stated with its policy-clause
   rationale, not silent.

## Smallest safe correction

One checked-in `cases.json` (or equivalent) keyed by the 32 contract names →
`{expectedExit, expectedFindings, fixture, rationale:<policy clause>}`, plus a
measure that (a) reads its population from that file at `--revision`, (b)
diffs name sets before running, (c) prints one row per case. That converts a
self-grading, glob-sized denominator into a frozen, re-derivable one — the
r21 baseline-list precedent already landed in this lane.

## Disposition

Fixable defect class, not a reject-the-axis tradeoff: the capability itself is
sound; only the counting surface needs pinning. No tools installed; read-only
seat; no lane writes beyond this report.
