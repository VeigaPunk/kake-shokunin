# Review 2.1.2 — No Keyboard Trap

**Verdict: Agree; no actionable card defect found.** Axes reviewed: operability and freshness. This is an author-side, read-only review of the assigned card against the pinned WCAG 2.2 source; no website was assessed.

- **Identity, quote, and status:** `id` `2.1.2`, title `No Keyboard Trap`, level `A`, and source URL `https://www.w3.org/TR/2024/REC-WCAG22-20241212/#no-keyboard-trap` match the saved criterion (`source-wcag22.html#no-keyboard-trap`, lines 1132–1140; `population.json`, lines 196–202). The `sourceQuote` — “focus can be moved away from that component using only a keyboard interface, and, if it requires more than unmodified arrow or tab keys” — is 24 words, contiguous within the criterion's `normativeText`, and preserves its keyboard-exit condition. `status` is `not-assessed`.
- **Check and evidence:** `publisherCheck` correctly checks keyboard entry and exit, then the two branches in the criterion: exit via standard methods, or an advised method when something beyond them is needed. `evidenceNeeded` asks for the keys used to enter and leave, the observed result, and the advice when a non-standard exit is needed; it therefore does not treat advice alone as proof that focus can leave. The linked `keyboard interface` definition (`#dfn-keyboard-interface`, lines 3177–3197) includes keyboard input emulation and distinguishes pointer-device operation; the card's “keyboard only” wording does not narrow the check to a physical keyboard.
- **All-content scope:** `publisherCheck` says “All content on the page is in scope, even content that is not used to meet other criteria.” This is not an overbroad criterion-specific claim: the note under `#no-keyboard-trap` says all page content must meet 2.1.2, and §5.2.5 `#cc5` explicitly includes 2.1.2 among the criteria that apply to all page content, including content not otherwise relied upon (lines 2222–2227). The inclusion of embedded and third-party components is consistent with that scope.
- **Failure example and limitation:** `failureExample` describes focus cycling within an embedded player, no working exit, and no exit instructions; its stated result that a keyboard user cannot reach the rest of the page is a concrete failure of the first requirement, not merely a failure to follow an informative suggestion. `limitation` explicitly says source inspection and automated tools cannot establish runtime focus behavior and makes no pass/fail or conformance claim from packet evidence. Its hands-on testing language is a conservative review-workflow limitation, not a WCAG requirement attributed to the source.

No correction is needed for this card.
