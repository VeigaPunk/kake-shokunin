# Round 30 wave 2 — runner case setup safety

Axes: operability (assigned); freshness is not implicated. This is an advisory falsification, not a remediation.

## Findings

1. **HIGH — `case.json` setup can mutate arbitrary paths outside `--tmpdir`.** `mkdir`/`fifo` path validation checks only non-empty strings; `work_dir / path` accepts both `..` traversal and absolute-path reset. Reproducer inputs: `/fast/scratch/hyaku/kake-r30/w2/SentinelRunnerSetup/probes/fixtures/fifo-dotdot/case.json:1` (SHA-256 `0f9bd64c3b4f1c429d1ccc0edc5f0b193273c364f379bd65f9027c44fd0830a0`) and `/fast/scratch/hyaku/kake-r30/w2/SentinelRunnerSetup/probes/fixtures/fifo-absolute/case.json:1` (`0ede473fd31f14346ef22545646f8a30c19e71feba1f3e1d3de2411c37c38942`). Both replaced sandbox victim files outside their respective tmpdirs with FIFOs; `stat` observed `fifo`. The `mkdir` probes created `/fast/scratch/hyaku/kake-r30/w2/SentinelRunnerSetup/probes/dotdot-outside-tmp` and `/fast/scratch/hyaku/kake-r30/w2/SentinelRunnerSetup/probes/absolute-outside-tmp`. Impact: arbitrary local file removal/replacement and directory creation with runner privileges. Smallest fix: reject absolute and `..` paths, then enforce resolved setup destinations remain inside the copied case before mutation.

2. **HIGH — fixture Git hooks and local config execute code.** `git_init` + `git_commit` runs `git add` and `git commit` in the copied case; the runner does not discard case `.git` state or disable hooks. A fixture hook wrote `/fast/scratch/hyaku/kake-r30/w2/SentinelRunnerSetup/probes/hook-ran`; an included `.git/config` setting `core.hooksPath` to the external sandbox hook wrote `/fast/scratch/hyaku/kake-r30/w2/SentinelRunnerSetup/probes/config-hook-ran`. Both marker contents confirmed execution. Evidence: `/fast/scratch/hyaku/kake-r30/w2/SentinelRunnerSetup/probes/fixtures/git-hook/.git/hooks/pre-commit:1-2` (SHA-256 `a1fa05f40210e9039c7012d16ed76269cd4abc4f20ccabb01cfdc454288fd304`), `/fast/scratch/hyaku/kake-r30/w2/SentinelRunnerSetup/probes/fixtures/git-config/.git/config:1-6` (`cb5ff317247f64394f27a2dd6c8f88f17edfdb721370ce287eac76516069f9e1`), and `/fast/scratch/hyaku/kake-r30/w2/SentinelRunnerSetup/probes/config-hooks/pre-commit:1-2` (`5db3689227cf691f12c185bb4be24153ae40dc2558500b3664cc6675af083e5c`). Impact: arbitrary code execution, including code outside the fixture copy. Smallest fix: never honor a fixture-provided `.git`; create a clean repository with hooks and config-driven filters disabled for setup operations.

3. **MEDIUM — `root` traversal reads outside the case and tmpdir.** `root` rejects leading `/` but accepts `..`; the gate receives `work_dir / root`. Reproducer: `/fast/scratch/hyaku/kake-r30/w2/SentinelRunnerSetup/probes/fixtures/root-escape/case.json:1` (SHA-256 `9bf5cd980ca9c4903fe6c8d36a64f2d96b155e9881348f1ff53093a8b651876a`) pointed at `/fast/scratch/hyaku/kake-r30/w2/SentinelRunnerSetup/probes/outside-canary/population.json`, containing duplicate member names. The gate returned the expected `input_invalid/document_duplicate_key`, proving it read that outside input. Smallest fix: reject `..` and verify the resolved root stays under `work_dir`.

4. **MEDIUM — symlink case directories escape the fixture root.** Discovery uses `path.is_dir()` and copying uses `shutil.copytree` without rejecting symlinks; `/fast/scratch/hyaku/kake-r30/w2/SentinelRunnerSetup/probes/fixtures/symlink-case` pointed to `/fast/scratch/hyaku/kake-r30/w2/SentinelRunnerSetup/probes/outside-case/case`. Its external `/fast/scratch/hyaku/kake-r30/w2/SentinelRunnerSetup/probes/outside-case/case/case.json:1` ran and created `/fast/scratch/hyaku/kake-r30/w2/SentinelRunnerSetup/probes/symlink-case-outside-tmp`; the case passed. Impact: runner reads and copies arbitrary external directory contents as fixture data, then processes its setup. Smallest fix: reject symlink case entries and require each case's real path to remain within the fixture root before reading `expected.json` or `case.json`.

5. **MEDIUM — setup list size and non-Git work are unbounded.** `case.json` is read and parsed wholly, and `apply_setup` iterates every operation; the per-process timeout does not bound `mkdir`/`fifo` setup work. A 2,600,012-byte case with 100,000 `mkdir .` entries was accepted and completed. Evidence: `/fast/scratch/hyaku/kake-r30/w2/SentinelRunnerSetup/probes/fixtures/large-setup/case.json:1` (SHA-256 `359d949d4e11db1d240aafdd5f7792ea7efeaa639f7afc2323866d6cd6689505`). Impact: attacker-controlled memory/CPU exhaustion. Smallest fix: bound `case.json` bytes and setup operation count (and apply an overall setup budget).
