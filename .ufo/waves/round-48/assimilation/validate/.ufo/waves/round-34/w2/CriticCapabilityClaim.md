## Findings
1. **MEDIUM — Earned only on evidence the round says does not count.** The capability runs: I reproduced the counter, the selftest and the real-input run, and the code parses HTML. The row also entered in the same round (24a1647). But the C1 after-value ends with "a capability row enters `## Capabilities`" (SCORECARD.md:1212). The measured results say the three checks that separate the tool from a lookup table "were written after the finding and do not count toward C1". The row cites those three checks as its evidence (SCORECARD.md:195). So C1 has two parts. The declared measure (28/28) is met, but by the round's own statement it does not show the capability. The row's entry rests on checks added after declaration. That is a post-hoc change of what the evidence is, and nobody discloses it as such. Impacted axes: operability, calibration. Fixable by wording (see R1); the judge has to decide whether a row may enter on undeclared evidence.
2. **MEDIUM — 28/28 is no longer a fair capability measure, and the table cell overstates it.** The measured-results cell says "28 of 28, all four constants rejected" with no qualifier (SCORECARD.md:1245). The necessary-not-sufficient caveat comes only in a bullet below the table. In the row, the caveat comes after the evidence pointer that leads with the 28/28 command. The disclosure is there, but it sits in the wrong place for a reader who reads only the cell. Correction: put "(necessary, not sufficient: a lookup tool also scores 28/28)" in the cell itself.
3. **MEDIUM — The real-input run is neither a held-out check nor an independent check of the rules.** (a) Its expected counts come from the committed C2 receipt, and its observed counts are committed in `verification/real-input-at-5613071.json`. A table keyed on ds4cc paths could replay them, just as dcef39b5 replays the matrix. "The lookup tool fails it" holds only for that one control [INFERENCE: I did not build a path-keyed replay]. (b) The C2 recount uses the same rule definitions as the tool: exact `property=`, non-empty content, `name=` ignored. Agreement therefore cannot catch a wrong rule definition (see finding 4). (c) On real input, only the og_required_missing rule fires. og_type_multiple, og_url_not_absolute and og_url_not_canonical have zero real instances: all 87 og:url values equal the canonical link. Those three rules fire only on fixtures the author made. Impacted axis: operability. Correction: the row should say the real-input run exercises the missing-property rule, and that the other three rules are shown only on author fixtures.
4. **MEDIUM — The row's "(S067)" attribution conflicts with S067 on og:image:url.** S067.txt says "og:image:url - Identical to og:image", and S068.txt says "og:image:url Equivalent to og:image". Probe cx/A-image-url-only has og:title, og:type and og:url plus `og:image:url` only. The tool returns failed-policy with og_required_missing og:image, exit 1. Neither the docstring (link_preview_audit.py:23-35) nor the row discloses this. ds4cc does not use og:image:url (0 pages in the retained archive), so the real-input result does not change. Correction: disclose it as lane policy ("only `property="og:image"` counts; og:image:url, which S067 calls identical, does not"), or accept og:image:url and add a fixture.
5. **LOW — "an og:url that differs" and "a non-absolute og:url" check only the first og:url.** Probe cx/E-second-ogurl has a first og:url equal to the canonical link and a second og:url of `https://evil.example/`: clean, exit 0. Probe cx/K-second-ogurl-relative has a second og:url of `/rel`: clean, exit 0. Code: link_preview_audit.py:207-209 (`og_urls[0]`). Correction: say "the first og:url".
6. **LOW — The row leaves out limits that the docstring discloses.** "Exact string comparison" is missing from the row. Probe cx/F flags `https://ex.org` against a canonical `https://ex.org/`, and probe cx/G flags `https://EX.org/p/` against `/p/`. Both pairs are equal under URL parsing, and both get og_url_not_canonical. The `<base>` limit is also missing. Probe cx/J has `<base href="https://ex.org/q/">`, canonical `x` and og:url `https://ex.org/q/x`, and it is flagged not-canonical. The `name=` limit is missing too. Correction: add these limits to the row's "no … claim" list (see R2).
7. **LOW — Duplicate attributes take the last value, but HTML parsing takes the first.** Probe cx/B has `<meta property="og:type" property="og:image" content="website">`. The tool reports og:type missing and treats og:image as present. An HTML-conformant parser would do the reverse. Code: `dict(attrs)` at link_preview_audit.py:78. This only affects malformed markup. Correction: keep the first occurrence of each attribute.
8. **LOW — The selftest receipt's name claims a revision that its content does not pin.** `verification/selftest-link-preview-at-5613071-tool.txt` records tool and fixtures as lane working-tree paths (`/home/vgpnk/Projects/shokunin/kake-shokunin/scripts/…`), with no revision and no sha256. I reproduced 29/29 at 24a1647, where the tool is byte-identical to 5613071, so the result holds. The provenance is still weaker than the name says. Correction: record the tool's sha256 in the receipt.
9. **PASS — "read-only and network-free" and the exit codes.** The network-namespace run, the strace run and the no-argument run all match the row. RCDATA probes cx/C (inside `<title>`), cx/D (inside `<textarea>`) and cx/I (inside `<xmp>`) report og:image missing, which is correct on Python 3.14.8. [INFERENCE: older html.parser releases may treat these elements differently; not run.] Prior holds and the sandbox threat model were not touched.
