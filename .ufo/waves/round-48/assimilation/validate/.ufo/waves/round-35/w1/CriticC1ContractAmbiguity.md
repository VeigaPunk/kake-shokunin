## Inputs where honest implementations can differ
Each item gives the input, the competing readings, and the text that decides it.

1. **Two identical og:url elements** (P1). Reading A gives `og_url_multiple`; reading B gives no finding because the value is the same. Text: "more than one non-empty `og:url` element" counts elements, and the og:type analogy does the same at audit.py:233. **Favours A.**
2. **A second og:url whose content is only a no-break space (U+00A0), or whitespace-only.** The contract never defines "non-empty". The base strips only ASCII whitespace (audit.py:60, :98), so an NBSP-only value is non-empty and gives `og_url_multiple`. A `str.strip()` implementation strips NBSP and gives no finding. The NBSP-only value can also become the "first non-empty" og:url, which then gives `og_url_not_absolute`. **Undecided by the contract**; "Every other round-34 rule … is unchanged" points weakly to the ASCII-only strip.
3. **The first og:url is relative, the second is absolute and equals the canonical link.** Text: "The first non-empty og:url still gets the absolute check and the canonical comparison". Reading A runs both, giving `og_url_not_absolute` plus `og_url_not_canonical`. Reading B keeps the base `elif` (audit.py:244-251), so a non-absolute og:url is never compared. Both readings also give `og_url_multiple`. **Undecided**: bullet (a) reads as A, and the "unchanged" clause reads as B.
4. **`<meta property=og:url>` directly inside `<svg>`** (P4). Reading A, the literal one: svg is open, so the meta does not count. Reading B follows the HTML spec: `meta` is a breakout start tag, so the parser pops the svg and the meta becomes an ordinary HTML head meta (html5lib shows ns=html under=-). Text: "inside an open … `<svg>` … counts neither", and "The element closes at its matching end tag". **Favours A**, against browser behaviour. A builder using a real HTML5 parser fails these cases.
5. **An unclosed `<svg>` icon followed by `<p>`, or by `</head><body>`, then the og:url** (P13, P15). Literal reading: svg is still open, so every later tag is excluded and four `og_required_missing` findings can appear. Spec reading: svg has closed and the meta counts. Text: "closes at its matching end tag". **Favours the literal reading**, with the same counterexample as item 4 but on realistic pages.
6. **A meta inside `<svg><foreignObject>` or `<math><mi>`** (P6, P14). The spec makes these HTML-namespace elements (integration points); the literal reading excludes them. Text: "inside an open `<svg>` or `<math>`". **Favours exclusion.**
7. **`<template><svg></template>` then an og:url** (P3; also `<math><svg></math>`, P12). Reading A uses per-element counters: the svg is still open and the meta is excluded (literal reading: []). Reading B uses a stack: `</template>` pops the svg too and the meta counts (html5lib agrees). Text: "closes at its matching end tag, nesting is counted" does not say whether an end tag closes the foreign elements opened inside it. **Undecided.**
8. **Self-closed `<template/>`** (P7). Reading A, by analogy with svg, opens nothing and the next meta counts. Reading B follows the spec, which ignores the self-closing flag on non-void HTML elements: the template opens and the rest of the page is excluded (html5lib: under=template). Text names only "a self-closed `<svg/>` opens nothing". **Undecided.** `<math/>` (P8) is also unnamed, but both readings agree that it opens nothing.
9. **A stray `</template>` before any `<template>`, then `<template>…</template>` and an og:url** (P9). A counter that clamps at zero excludes only the inside meta, and the spec agrees. A naive counter goes to -1 and then 0 inside the template, so it counts the template's meta and can give `og_url_multiple`. Text: "closes at its matching end tag" (a stray end tag has no match). **Favours clamping.**
10. **An unclosed `<template>` at end of file** (P2). Everything after it is excluded under both readings. **Decided** by "matching end tag"; html5lib agrees.
11. **A canonical link inside a template, then a different canonical link outside.** Reading A: the outside link becomes the first canonical link and is compared. Reading B: the first-canonical slot was used up, so there is no canonical link. Text: "counts neither as an Open Graph property nor as the canonical link". **Favours A.** Separately, the tool docstring at audit.py:33-35 says canonical links inside template and svg count. The repair has to rewrite it.
12. **A `<template>` tag inside `<noscript>`** (P11). `html.parser` and html5lib (scripting off) both open the template, so the later meta is excluded. A browser with scripting on treats noscript content as raw text, and the meta counts. **Undecided**, low weight. `<title><template>` (P10) gives the same result on Python 3.12.15 to 3.15.0 here (all of them treat title and textarea as RCDATA), so it does not split implementations on this host.
13. **A manifest whose only page is unreadable.** Reading A: `page_unreadable` for that page, exit 2. Reading B: nothing auditable, so the fault is manifest-level and gives `input_invalid` with no page. Text: "gives `page_unreadable` for that page", and the manifest-level clause is limited to faults the base already treats as manifest-level. **Favours A.**
14. **A page file missing from disk, beside readable pages.** The list "(not UTF-8, not a regular file, over the read bound)" could be exhaustive. If it is, a missing file is a manifest fault and nothing is audited. If it is only examples, the missing page gives `page_unreadable` and the others are audited. The base routes a missing file through `is_file()` to `page_unreadable` (audit.py:195-211). **Undecided by (c)**; the "unchanged" clause points to `page_unreadable`.
15. **A page entry naming a directory, beside readable pages.** The counter can build this, because a parent directory of another case file can be named as a page. Text: "not a regular file". **Decided**: `page_unreadable`, and the other pages are audited. A FIFO page cannot appear in the sealed set: the counter writes only regular files (sealed_count.py:154-160), so FIFO handling is unmeasured.
16. **The same unreadable file listed twice, or two pages sharing one URL.** Reading A: one `page_unreadable` per manifest entry, so two findings. Reading B: deduplicate by page. The projection is a multiset (sealed_count.py:113-118), so the readings score differently. Text: "for that page". **Undecided**; the base emits one finding per entry.
17. **A Latin-1 page that declares `<meta charset=iso-8859-1>`, beside readable pages.** Text: "not UTF-8" makes it `page_unreadable`, even though an HTML-faithful reader would decode it. **Decided.**
18. **Readable pages with policy findings beside an unreadable page.** **Decided**: the verdict is `could-not-evaluate`, exit 2, and the findings are `page_unreadable` plus the policy findings ("reported beside the input findings. The verdict stays `could-not-evaluate` (exit 2)").
19. **A per-page path escape that is caught only in the audit loop** (audit.py:205-209, which emits `input_invalid` with a page). Is that a "manifest-level fault … with no page"? **Undecided.** The case is reachable only if the filesystem changes between manifest load and the audit loop, so the counter cannot test it.

I cannot tell whether any sealed case uses these inputs.
