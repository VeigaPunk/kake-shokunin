## Overlaps with C1's contract, and the convention C1 should follow

- **O1 exit ladder — already the lane standard.** 0 clean / 1 policy / 2 input / 64 usage is defined three times, identically: `freshness-sweep.mjs:15-16`, `canonical_audit.py:28-31`, `live_snapshot.py:12-13`. C1's `clean/failed-policy/could-not-evaluate` are verbatim `canonical_audit`'s names; reuse them, invent nothing.
- **O2 manifest envelope — one convention, two carriers.** `{"version":1, <array>}` behind `--manifest PATH`, body paths relative to the manifest's directory, is used by `canonical_audit` (684, 706, 720), `live_snapshot.audit` (134-143) and `receipt_replay.make_reproducer` (498-520). C1's `checks` where they use `pages` is the only difference. C1 should also copy `canonical_audit.read_page_bytes` (581) as the reference rejection of absolute/escaping/symlink body paths that bullet (g) demands.
- **O3 field names diverge by contract — record the mapping.** `pagesChecked`→`checksEvaluated`, `findings[].id`→`.check`, `findings[].page`→`.target`, and `canonical_audit`'s `exit_code` becomes C1's process exit. C1's names are frozen by the sealed cases; put this mapping in `source_recheck.py`'s docstring so a later reader does not "unify" the two and break C1.
- **O4 reason vocabulary — snake_case tokens, shared `input_invalid`.** `input_invalid` means the same whole-input fault with a null subject in both (`canonical_audit.py:33,748`); C1 must keep the token and the meaning. Other reasons (`gone, http_error, moved, quote_missing, unsupported_type, charset_unsupported, check_invalid`) are new but fit the same shape. Note `quote_missing` ≠ `accessibility_packet`'s `quote_not_from_source` — different algorithms, both live.
- **O5 HTML text — reuse the shape, not the function.** `visible_text` (`fetch_sources.py:45-51`) is the lane's HTML→text, but C1 bullet (c) differs in three ways: comments removed *first* (before script removal), `template` removed per-element, and tags removed as "`<` + letter/`/`/`!` up to next `>`" rather than `<[^>]+>` (which stops at a `>` inside an attribute). Calling `visible_text` would pass most bodies and fail the sealed cases on those edges. `live_snapshot` uses `html.parser` (`canonical_audit`) instead of regex — also not C1's rule.
- **O6 quote match — C1's rule is new.** `accessibility_packet` checks word-boundary containment of a whitespace-collapsed quote in whitespace-collapsed text (23-25, 125). C1 checks NFKC then `isspace()`-deletion, case-sensitive. Do not swap in `normalized()`; its punctuation regex would differ. `receipt_replay:344`'s raw `anchor in base_text` is a third, weaker variant.
- **O7 no-network re-audit is already a pattern.** `live_snapshot --reaudit` is exactly C1's posture: verify recorded metadata, length and digest first, then judge the stored bytes, never the network (168-188). C1 should follow that order — verify the body file, then status, then redirects, then text — and state in its docstring that it never fetches, mirroring `live_snapshot.py:1-13`.
- **O8 registry has no quote column.** `corpus/SOURCES.md:7` is `id|source|kind|tier|scope|anchor|teaches|status|opened|recheck|used-by`: `anchor` is a locator ("lines 17-20"), `teaches` is the claim. C1's `quote` has no existing field, so C1 cannot be driven from SOURCES.md without a generator (out of C1's contract). Cadence pins live in `corpus/knowledge/freshness-pins.json` (`schema: kake-freshness-pins-v1`), which is where a driver would keep a last-fetch sha; C1 reads neither file.
- **O9 one real convention clash.** `sources-census.sh` uses 0/1/2/**3** with no 64 (16-18). C1 must not adopt it: every Python tool C1 resembles uses 64 for usage (`canonical_audit.py:31`, `live_snapshot.py:12`, `receipt_replay.build_parser` 565-576). A driver that chains census and `source_recheck.py` will misread exit 1 (census: E findings; C1: failed-policy) — worth one line in C1's docstring.
