INFERENCE TRAPS:

1. Equating Baidu's "内容死链" (content dead link) or Yahoo's 200 error page with Google's industry term "soft 404": Neither S421, S422, S419, nor S420 uses the phrase "soft 404". Treating content dead links as identical to soft 404 without explicitly marking it as lane inference violates quote truth.
2. Assuming Baidu supports a head meta-tag fallback for dead links: Yahoo S419/S420 explicitly provides a fallback setting ("メタタグを使ったインデックスへの登録拒否" [S419]). Baidu S421 provides no meta-tag fallback; it strictly requires setting HTTP 404 and submitting a silian file ("请一定设置为404" [S421]).
3. Conflating Baidu's dead-link submission tool restriction with crawler recognition: S421 states the submission tool only recognizes 404 ("仅识别404，" [S421]), whereas S422 states Spider 3.0's recognition model can autonomously recognize content dead links ("以及大多数内容死链、跳转死链等低质网页" [S422]). Claiming Baiduspider cannot recognize dead links without tool submission conflates tool constraints with crawler capabilities.
4. Assuming Baidu's dead-link submission tool accepts HTTP 410 Gone: S421 explicitly rejects non-404 status codes for the tool ("仅识别404，请一定设置为404" [S421]; rejecting 403 and 500). Claiming standard HTTP 410 can be submitted is unsourced inference.
5. Projecting crawl budget or emergency crawl-rate backoff onto Baidu dead links: S421 notes dead links may affect site evaluation ("影响网站整体评价" [S421]), not that Baiduspider applies Google's hostname-wide crawl-rate reduction (S274) or budget-shifting mechanics (S273).

PATTERN:

Across search engines, the "200-that-lies" problem occurs when a removed or invalid page answers HTTP 200, preventing crawlers from recognizing the deletion from the protocol status alone: Yahoo! JAPAN notes the crawler cannot recognize the deletion ("クローラーは削除されたウェブページと認識できず、" [S419:18]) and continues crawling ("巡回を続けます" [S420:36]), while Baidu defines this as a content dead link where the server returns 200 ("服务器端返回HTTP状态码200" [S421]) for missing content ("内容已经变更为不存在、已删除或需要权限" [S421]). Both engines instruct publishers to remedy this by configuring HTTP 404 ("サーバーが「HTTP 404 Not Found」" [S419:26, S420:46]; "页面设置404，一定是404页面" [S421]), but they diverge sharply in remediation architecture and autonomy: Yahoo offers a client-side head meta-tag fallback ("メタタグを使ったインデックスへの登録拒否" [S419:35]) while leaving the crawler passive, whereas Baidu provides no meta-tag fallback, strictly gates its dead-link submission tool to 404 ("仅识别404，" [S421]), yet deploys autonomous machine learning on the crawler ("启用了全新的死链识别模型" [S422]) to identify content dead links directly, while still affirming that protocol 404 remains optimal ("协议死链是最好的选择" [S422]). Meanwhile, Google's held corpus admits only crawl scale-back on server trouble ("scale back its crawling", S286:10) and explicitly disclaims a soft-404 remedy ("A soft-404 remedy is not claimed", S286:14), confirming that crawl hygiene rules cannot be generalized across engines without primary documentation.

VERDICT: Sourced cross-engine contrast and safe cross-link boundaries established across Yahoo, Baidu, and Google without inference.
