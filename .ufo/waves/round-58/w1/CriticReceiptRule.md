# CriticReceiptRule

Attack on the round-58 receipt rule ("committed once, after the run, never rewritten; no placeholder" — contract.md:11-13, contract.json `receiptRule`) as an operating procedure over the L1's T0/T1 landing (C2/C3 after-receipts at T0, C1 receipt at T1). Evidence: counters and history at tip cc8da16 (base 0440485, freeze fff3eea); C1 counter runs reproduced in a scratch fixture (git fixture under /fast/scratch/hyaku/kake-r58/CriticReceiptRule, deleted after the runs).

## BREAKS:

1. **The rule's "re-run lands under a new file name" is impossible for the C2/C3 after-receipts — C1's frozen predicate only accepts exactly two `after-c[23]-*.txt` files.** `c58_receipt_rewrites.py:59,198-206` counts every file matching `^\.ufo/waves/round-58/controls/after-c[23]-[^/]+\.txt$` at the tip and requires `new_receipts == 2`. Simulated: T0 with `after-c2-resolver-cases.txt`+`after-c3-quote-truth.txt` → `new_receipts=2 met=True` (exit 0); adding a third receipt `after-c3-quote-truth-v2.txt` (the "new file name" the rule demands) → `new_receipts=3 met=False` (exit 1). So if a seat finds a defect after T0 (the assigned case), neither rewriting the old receipt (→ `new_rewritten=1`) nor adding any new `after-c[23]-*` file keeps C1 green. The count also does not enforce distinctness: two `after-c2-*` files would satisfy `==2`; exactly one C2 plus one C3 must be enforced procedurally.

2. **Selftest receipt re-run after a counter fix.** C3's selftest is a stub in v1 (contract.md:72; derive_c58_quote_truth.py:116-118) and is ported/hardened this wave; SKILL-row tallies are drafted as `<N>/<N>` placeholders (ScribeSkillRows). Breaks: (a) committing a selftest receipt before the final counter bytes are frozen, then re-running into the same path → M event on a round-58 controls path → `new_rewritten=1` (simulated: any M on a controls path flips it); (b) committing a `<N>/<N>` or `pending` tally → placeholder receipt, class D1 — C1 does not check receipt content, so it passes; (c) touching the frozen junk-control receipt `controls/c1-selftest-v1.txt` (freeze commit fff3eea) in any way → `new_rewritten`.

3. **Census-after written twice.** Round-57 precedent: `census-after.txt` (T0, 31b61a4) and `census-after-build.txt` (build, cddef5b) both committed — blob-identical (git show diff empty), yet the SCORECARD names only `census-after.txt`. `validate_append.sh:1-5` mandates re-running the append validation after ANY edit to corpus/SOURCES.md or the two entries. Breaks: (a) the second run written to the same `census-after.txt` → M → `new_rewritten=1`; (b) two differently-named censuses whose outputs differ (pre- vs post-repair) leave no canonical census — reports must say which one is the round's census.

4. **SCORECARD-pin rides are the historical rewrite vector, and they are still open.** Round-56 commit ad06cb8 ("measurement receipts, SCORECARD and LOG revision pins") modified `after-c1-selftally.txt`, `after-c2-quote-truth.txt`, `c2-selftest.txt` — three of the 13 undisclosed events in the C1 base list (base receipt, 19 events). The r57 C1 receipt also carries a `revision:` line, and the r57 scorecard asserted "none is ever rewritten" right after the fill (31b61a4 → 20217f2, D1). Any relabel of a round-58 receipt's revision line to match a later scorecard pin → `new_rewritten=1` even if disclosed (contract.md:40: "even disclosed" still fails). Scorecard/LOG edits themselves are not receipts and do not move C1; the receipt *labels* are the trap.

5. **A receipt the L1 must correct after T0 has no safe edit — not even the C1 receipt.** Any M/D/readd on any committed round-58 controls path counts from `new_rewritten`; any added `after-c[23]-*` counts into `new_receipts` (break 1). The C1 receipt is written once at T1 and can never be repaired: editing it flips `new_rewritten` at every later tip, permanently failing C1. So the C1 receipt (and both after-receipts) must be perfectly reviewed before commit; post-T0 findings must go through the re-run naming in PROCEDURE step 5 instead.

6. **Counter limits that the procedure must close by hand:** C1 checks presence, not content — a `pending`/placeholder `after-c3-quote-truth.txt` passes (`new_receipts=2`), so the no-placeholder rule rests on reviewers reading receipt bodies; and `met` does not require the ledger to be present (`measure()`, {163-206: `ledger_present` is not in the predicate), so the C1 receipt must be written only after the ledger exists and covers every event at T0 (base 19 + none this round), or a zero-disclosure pass is misrecorded.

## PROCEDURE:

1. Freeze all fixes before any after-receipt: counters final (including the ported C3 selftest), entries final, `scripts/id_resolver.py` final. T0 is the last act of the build; run seat findings that would change the measured bytes before T0, not after.
2. Run each counter's final selftest on its final bytes, then commit `controls/c1-selftest-final.txt`, `controls/c2-selftest-final.txt`, `controls/c3-selftest-final.txt` with real tallies (no `<N>/<N>`, no `pending`), once each. Never re-run into an existing name; never modify `controls/c1-selftest-v1.txt`.
3. Append the registry rows, run `validate_append.sh` until exit 0, then write `controls/census-after.txt` once. Any later registry edit forces a re-run: write it under a fresh name (e.g. `census-after-repair.txt`), never edit the first, and name the canonical census in LOG/SCORECARD.
4. At T0: run C2 and C3 at the exact tip, save outputs to `controls/after-c2-resolver-cases.txt` and `controls/after-c3-quote-truth.txt`, verify each receipt's body is the real run (exit 0, predicate line), commit once.
5. If a seat finds a defect after T0: do NOT edit, delete, rename, or add any `after-c[23]-*` path. Fix the object, re-run the counter at the new tip, and land the output under a name that does not start with `after-c2-`/`after-c3-` (e.g. `controls/recheck-c3-quote-truth-<shortrev>.txt`); leave the original after-receipt untouched and note supersession in LOG/SCORECARD. (Simulated: this is the only C1-green re-run path; any `after-c[23]-*` addition makes `new_receipts=3` → red.)
6. Before C1: confirm `.ufo/waves/round-58/receipt-rewrites.json` exists at the tip, is JSON with an `events` list, and covers every event at T0 (base 19; expect zero this-round events). Run `c58_receipt_rewrites.py --root <lane> --revision <T0>`. Only if `met=True` (exit 0), write `controls/after-c1-receipt-rewrites.txt` from that exact run and commit once (T1). Never commit the C1 receipt from a failing run.
7. After any commit, never modify any file under `round-58/controls/`; the only permitted addition is a NEW file whose name avoids `after-c[23]-*.txt` and names the run it records.
8. SCORECARD/LOG pins reference receipts by path + revision; never edit a receipt to align its revision line with a pin. If the measured state changes, append a successor pin line naming the new receipt; keep prior pins and receipts intact.
9. After T1, non-receipt commits (settlement, reports, SCORECARD, LOG, SKILL tallies) are safe, but re-run the C1 counter at each new tip and require `met=True` before finalizing; a red result means a controls/ mutation or an extra `after-c[23]-*` file — find and revert it (no other cause exists).
10. Placeholder guard: have reviewers read every receipt body (after-c*, census, selftest finals) before commit; the C1 counter cannot see a `pending` body, so human eyes close the D1 class this round.

VERDICT: The rule is sound but the frozen C1 predicate (new_receipts == 2, new_rewritten == 0) makes post-T0 re-runs of C2/C3 illegal under any `after-c[23]-*` name — the L1 must land all fixes before T0 and use non-`after-c[23]-*` recheck names for any unavoidable later re-run.
