## HOLES (fix proposals):

1. Parse the intended axis table in each round section and require an actual row whose first/axis cell equals the requested axis. Do not infer on-axis status from any pipe line containing the word; reject/avoid duplicate round sections or define unambiguous handling.
2. Make pointer extraction consistent with the stated pointer contract: recognize repo-relative path mentions outside backticks and HTML code spans (or explicitly constrain and validate the syntax); reject unrecognized path-like tokens rather than silently ignoring them. Normalize/reject Unicode slash lookalikes if they are intended as path spellings. Preserve whitespace-containing path tokens as a unit instead of splitting them into unrelated tokens.
3. For `superseded_kept`, ignore HTML comments and other non-rendered content, and require each base cell as visible history outside the measured table.
4. Require exactly one canonical axis table (or anchor it to a defined location/heading); multiple matching headers should be unevaluable rather than silently selecting the first. This prevents a compliant decoy table from shadowing the assessed table.
5. Keep tally/receipt support limitations explicit and reviewer-checked; if the counter is intended to establish a result, bind the tally to the receipt's structured result field and require that the tally-host blob is itself an on-axis receipt.

The strongest undisclosed defects are broad `on_axis()` matching, ignored path forms, hidden-comment retention, and first-table shadowing; tally coincidence is an expressly stated limit, and score-string comparison resisted the tested changes.
