# CriticC2Semantics

## CASES:

- **K8 — Agree.** CommonMark 0.31.2 §4.6, HTML block type 2: `<!--` begins a comment block through a line containing `-->`; contents are not Markdown, so a hidden table-shaped row is not a registry entry. The current `parse_registry` (resolver lines 107–142) skips fences but not comments, explaining the false registration. Ensure comments are skipped as blocks, including a same-line close and EOF termination.
- **K9 — Agree, with an important boundary.** CommonMark 0.31.2 §4.3 defines `Subsection` followed by `---` as a level-2 setext heading, so registry section parsing should stop there. But `---` alone after a blank line is a thematic break (§4.1), not a heading; the section should continue. A GFM table delimiter such as `| --- | --- |` is not a setext underline (§4.10 Tables). Do not implement this as “any dashes end section.” Existing `SECTION_END_RE` only handles ATX headings (resolver line 48).
- **K10 — Agree.** The cited file is reachable through an in-lane directory symlink, so omitting it misses a citation and can falsely report green. Current worktree traversal uses `os.walk` without `followlinks=True` (resolver lines 196–216). Follow only targets contained in the lane. The case does not specify alias-path rendering or traversal-cycle behavior.
- **K11 — Agree.** A committed symlink’s blob is its target path, not file content; treating that text as Markdown can invent citations and miss the target’s citations. Resolving an in-tree target matches ordinary worktree reads and the case’s explicit intent. Current revision scan reads each listed path with `git show` (lines 178–194), so mode-120000 entries are parsed as target strings. The dangling link contributes no body and must not create F11.
- **K12 — Agree: exit 2, not 1.** An out-of-lane registry is not the lane registry, so the tool has no valid measurement; exit 1 would falsely claim a dangling-id result against untrusted input. Worktree `lane_registry` follows the symlink via `isfile`/`open` without a containment check (lines 168–174). Rejecting it as unevaluable is appropriate.
- **K13 — Agree on counting; output spelling remains unspecified.** An undecodable filename does not make the committed citation unevaluable. Current `_nul_paths` decodes path bytes with UTF-8 replacement (line 88), then `git show` uses that corrupted path (lines 183–190), causing the failure. The case correctly requires the citation and dangling result, but does not specify how `cited-by` renders the byte name (replacement character versus escaped bytes); standardize that if output compatibility matters.
- **K14 — Agree: exit 2.** A subdirectory argument is not the repository root; Git otherwise resolves commands against an ancestor and can measure a different lane, producing false provenance/green. `evaluate` only applies `abspath` (line 254) and has no toplevel check. Treating the scope as unevaluable is correct.

## CONTRACT RISKS:

The strongest untested gap is revision-mode **directory symlink parity**: K10 tests a worktree directory symlink, while K11 tests only file symlinks. A tool could pass both while omitting citations beneath a committed symlinked directory; pin whether revision mode must follow such in-tree directories (parity implies yes). Following symlinks also needs cycle detection and bounded/deduplicated traversal; otherwise a cycle can hang, and aliases can produce repeated citing paths. K12 tests only a worktree registry symlink: revision-mode `git show <rev>:corpus/SOURCES.md` likewise returns a committed symlink’s target string, so pin its policy too. K9’s fixture appropriately tests a true setext heading, but should distinguish the thematic-break and table-delimiter cases above to prevent an over-broad dash rule. K13 should specify deterministic, valid-UTF-8 path rendering if stdout is a stable interface.

## VERDICT:

K8–K14 expectations are substantively correct for an in-lane source-id resolver; accept them. The smallest safe clarification is to add explicit non-heading `---`/GFM delimiter controls and specify safe, cycle-bounded symlink traversal plus revision-mode directory/registry symlink policy. K13’s output-path encoding is a compatibility clarification, not a reason to reject its citation expectation.
