# CriticC3Cheat

CHEATS:
- Whitespace collapse lets a quotation not present as an exact contiguous written phrase pass. `run_checks` normalizes the entire retained HTML with `re.sub(r"\s+", " ", raw.decode(...))` before quote validation (lines 367-369); `text_segments` then checks literal substring in that normalized text node (192-199, 211-213). A source node split by tabs/newlines or repeated whitespace can therefore accept a fabricated single-space rendering, although the retained source does not contain that span as written. This is a semantic/provenance weakness for the contract's “substring ... as written” rule. The supplied helper repeats the counter normalization (span_tools.py lines 22-24), so it does not independently expose it.
- `CHAR_CEILING=160` and the 25 whitespace-unit ceiling do not limit sentence count (counter lines 95, 405-410). A quote comprised of multiple short sentences can meet both ceilings, if unique and in one text node. The counter has no punctuation/sentence-boundary check. This is a quality loophole, not necessarily false source attribution; contract does not explicitly require one sentence.
- Article window is a string interval from the first occurrence of `class="devsite-article-body` to the first later `<devsite-content-footer` (183-189). It is not a parsed article boundary. Any unrelated text node in that interval—including preamble, embedded sample, or injected content—is eligible. Existing S425 HTML includes the real article inside `<devsite-content>` and extra page structures, so a crafted retained-body fixture can place unrelated text after that class marker and before the footer and satisfy `in_content`; the hash pins block substitution in the production run but do not make this extraction rule sound for counter mutations/fixture attacks.
- The “Last updated” test searches every raw text node in the full normalized document (C5 lines 382-386), not the article block. A script/JSON body is normally excluded by `text_segments`, but an HTML `script` containing a literal `>` can terminate the crude regex's tag match and expose subsequent script text as a pseudo-text segment. Thus placing `Last updated YYYY-MM-DD UTC` in a script/JSON text node can satisfy the test. The same lightweight parser risk applies to quotes.
- Heading extraction uses a regex over all `<h2>/<h3>` markup in the interval (202-208), including code samples; a literal `<h2>...</h2>` inside a `<pre>` sample can become the anchor heading and pass C5. It also does not require the heading to be rendered/visible article prose.
- C9's diff logic proves base lines were not deleted/replaced, then collects insert opcodes whose base insertion index is close to the stale line (621-646). It does not bind inserted content to the stale line's paragraph/list item. One may insert correction text into a neighbouring bullet and pass; the acceptance window is line proximity, not semantic attachment.
- C9 searches quote spans over joined inserted lines and only requires the tag substring on some inserted line (643-657). A quote inside inline code can qualify, because Markdown context is not parsed. It also accepts `S425` anywhere in joined block, including an HTML comment (`re.search(r"\\bS425\\b", block)`, 647-648): the source citation need not be visible. Together these allow tag/citation/quote signals without a reader-facing correction.

HOLES:
- No executable fixture evidence was produced in this review: the counter's selftest is explicitly a version-1 stub (lines 673-679), and deriving/running candidate fixtures would require recreating the entire repository contract/evidence state. The loopholes above are established from inspected code paths; specific 9/9 end-to-end outcomes are [INFERENCE], not measured.
- High-priority counterexample tests: HTML source has text `Google\n  crawlers` while entry quotes `Google crawlers`; a fixture changes a source quote to two sentence clauses under 160 chars; append irrelevant prose/code inside the article interval; put the exact update phrase in malformed script text containing `>`; put the cited heading markup in `<pre>`; insert the C9 correction as a neighbouring bullet; move its quote into `<code>` and put S425 only in `<!-- S425 -->`. Run each against a complete scratch fixture and assert individual condition behavior before treating it as a demonstrated kill.
- Smallest safe corrections: tokenize actual HTML with a standard parser and preserve text-node whitespace rather than normalizing source before substring checks; bind extracted text/headings/update line to parsed article semantics and exclude code/script/style and hidden/non-article containers; add an explicit one-sentence/one-clause quote policy only if contract intends that constraint; for C9 parse Markdown blocks and require a visible correction paragraph/list item directly attached to the stale statement, with citation and quote as rendered content (not code/comment). Then port these cases into the required selftest kill matrix.

VERDICT: Counter has several credible false-positive routes, especially C9 citation/attachment checks and regex-based HTML article/headings parsing; 9/9 is not yet mutation-resistant. Specific complete-fixture pass outcomes remain unverified.
