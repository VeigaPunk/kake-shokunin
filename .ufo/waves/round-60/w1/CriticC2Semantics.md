## CONTRACT RISKS:

- **CR1 — laundering via existential alignment (case #1).** The frozen rule is clean iff SOME alignment tag-leads every mid-file run. Adversary inserts `TAG, <dup-of-base-line>, evil, <dup>`: a non-leftmost alignment parks `evil` inside a tag-led run. Frozen text says exit 0; a reader says the file gained an untagged line. Either accept (document as disclosed limit, alongside "faithful correction") or v2-tighten to "every leftmost-maximal alignment" — must be decided BEFORE counters freeze; K15 forbids the naive greedy fix.
- **CR2 — "visible" is undefined (cases #9, K9, K10).** Rule excludes only HTML comments and backtick spans. Tags in fenced code blocks (15 corpus files have fences), link titles, headings, raw HTML attributes, or mid-sentence all count. Two divergent v1 readings: (a) fenced blocks excluded → K-untested divergence, (b) included → tag inside ``` block launders. The phrase "visible correction tag" promises render-visibility the test does not deliver. Pin K30a/b now; tighten in v2 if needed.
- **CR3 — tag convention collision (case #7).** Base corpus carries 13 `[r20-correction DATE: text]` and 5 `[r23-correction]` tags — neither matches the regex. A w1 author copying the r20 house style produces a real correction the guard flags. Frozen regex is a NEW convention; say so explicitly in the tool docstring, or accept `:…`-suffixed dates.
- **CR4 — no-newline/empty-base traps (cases #2, #16).** `split("\n")` semantics make base-without-final-NL → append-onto-last-line a `changed` (defensible) but EMPTY base → `x` a `changed` (surprising: pure append to an empty file reads as rewrite). Spec-level pin needed; corpus is currently all-NL-terminated so no live trigger.
- **CR5 — default scope misses 3/58 corpus files.** `corpus/knowledge/**/*.md` skips `accessibility-review-cards.json`, `freshness-pins.json`, `freshness-sidecar.json` — all rewritable silently. Deliberate (glob is `.md`) but undisclosed; one line in the docstring or a widened default glob is the fix.
- **CR6 — CLI ambiguity.** `--base` unresolvable vs missing both plausibly read as 2 vs 64 (K21 covers only flag-absent). `--scope` matching zero files: 0-clean vs 2-unevaluable unpinned. `--selftest` contract undefined — a mutant with a vacuous `--selftest` passes the counter untested. Finding line format `<kind> <path>[:<line>]` doesn't say which run's line `untagged_insertion` reports (first bad run? lowest across alignments?) — the counter checks only `kind+path` on stdout, so any line number passes.
- **CR7 — blind spots worth one docstring line each:** executable-bit/mode-only flips (content equal, mode 100755 — silent); file→directory transition (rule covers via "tree" but no case pins it); gitlink under scope (skipped as non-regular at both ends); scope paths outside the repo (`--scope ../../etc/**`) unnormalized; paths containing `"` or `\n` (git ls-tree C-quoting — core.quotepath) with exotic filenames.
- **CR8 — counter-level.** Counter asserts "expected exit AND expected finding kind + path" — so a tool printing `changed` AND `untagged_insertion` for one file (extra finding) still passes the case if the expected kind appears. Add a stdout-exactness clause (findings-set equality) to v1, or a mutant emitting every kind on every file scores 24/24. Also: `--seed` draws fixture ids — a deterministic mutant could hardcode; seed must vary content, not just names.

VERDICT: semantics buildable as frozen only after pins K23–K36 land; CR1 (existential laundering) and CR2 (fenced/attribute tags vs "visible") are the two real holes — accept-and-disclose or tighten now, because v2 may only tighten and K15 already forbids the greedy shortcut.
