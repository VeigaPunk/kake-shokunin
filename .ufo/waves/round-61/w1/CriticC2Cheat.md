# CriticC2Cheat

Scope: attack the c61_header_cases counter design (claim C2, operability). Evidence base: the frozen contract (`.ufo/waves/round-61/contract.md`, line refs below), the w1 worktree tools `scripts/header_audit.py` / `scripts/response_snapshot.py` (uncommitted, actively rewritten by peers — all observations on them are [worktree-in-flux]), and a 3-fixture demo I ran against the worktree audit tool from my scratch dir (results inline; scratch deleted after). No lane files were mutated; the audit tool was only executed read-only against my own fixtures.

## CHEATS:

**Cheat 1 — audit tool pattern-matches the 18 fixture manifests.**
Mechanism: the audit hardcodes fixture ids/URLs/manifest digests and prints the expected verdict per fixture instead of evaluating rules. Caught by frozen rule, partially: the counter builds "gate-built fixture manifests (seeded ids)" (contract line 164: "runs the audit tool as committed at the revision over gate-built fixture manifests (seeded ids) and"), so an id-keyed lookup fails on any seed; and the counter selftest controls include a "no tool, always-clean, always-exit-1, manifest-sniffing composite" (line 195) that must score a sniffing tool as failing. Residual gaps: (a) only ids are seeded — fixture *content* stays canonical per case, so a tool keyed on manifest-content digest passes all 18 on every seed; (b) the composite control is author-written, so an id-only sniffer "passes" the counter's detection while proving nothing about content keying; (c) if the counter writes expected outcomes anywhere under `--work`, a tool that greps its own fixture tree wins outright. Fixable defect, not a tradeoff: see T4.

**Cheat 2 — counter that reads the worktree.**
Mechanism: the counter (or the audit it spawns) resolves the real manifest and capture receipts from the working tree instead of committed bytes at `--revision`; uncommitted w1 edits then define the measured state and the named revision is decorative. This lane's `git status` already shows dozens of untracked w1 files, so worktree state is measurably non-canonical today. Caught by frozen rule: only for the tool side — "runs the audit tool as committed at the revision" (line 164). C1's tool spec carries the explicit committed-bytes rule (line 96 area: committed bytes only via git plumbing, never the worktree); the C2 counter section has no equivalent for its *inputs*. Fixable defect: see T1.

**Cheat 3 — manifest tuned per-outcome (declaring all expects false forces clean).**
Mechanism: expectation classes are gated by the manifest's declared bools, so the manifest author — not the tool — decides what can fail. Demo against the worktree audit tool, one dirty receipt (200, no HSTS, no CSP, `X-Content-Type-Options: sniff`): full expectations → 4 findings, exit 1; same receipt with every expectation declared false → `checks=1 findings=0`, exit 0. On fixtures this is by design (H16 pins it). On the real manifest it is NOT caught: R3 asserts only the run shape — "each bound to an existing capture receipt" (line 191) — and the verdict is recorded rather than asserted clean (line 187), so a vacuously-tuned real manifest still yields `cases_passed == 18 of 18` and the frozen predicate `met: cases_passed == 18 of 18` holds on an audit that checked nothing. The contract parks this under "whether the expectation classes are the right publisher policy (critic-checked)" (line 196); this is that check, and the hole is real. Compounding ambiguity: the contract's `content_type_present` class reads unconditional (a 2xx with no Content-Type is a finding), but the built tool gates it on the declared bool (`flags["content_type_present"] and 200 <= status <= 299`); my demo run 3 (expect false + receipt without Content-Type) confirms suppression. No frozen case discriminates the two readings — H16 uses clean headers — so w2 can mutate either way and still pass. Fixable defect: see T2, T3.

**Cheat 4 — capture receipts fabricated after the audit (receipt sha order).**
Mechanism: receipts are committed after the audit ran or invented without any fetch; at the measured revision the manifest is still "bound to existing receipts", existence being all R3 checks. Nothing pins commit order (receipts → manifest), receipt integrity (sha256/bytes vs body), capture metadata (fetchedAt on the access date, userAgent `round61`), or even leaves a committed trace of the audit run — the round-58 receipt rule covers `.ufo/waves/round-61/controls/` receipts only, not the capture tree. The related receipt-swap variant (check id bound to a different surface's receipt) is likewise invisible: the manifest `url` is never cross-checked against the receipt's recorded url/finalUrl. Caught by frozen rule: partly delegated, not counter-enforced — "whether the capture itself is honest" is delegated with "receipts are sha256-pinned and re-readable; sentinel-checked" (line 197). Tradeoff vs fixable: live-fetch honesty is genuinely sentinel territory, but integrity recompute and first-parent ordering are offline and cheap, so leaving them out is a fixable gap: see T5.

**Cheat 5 — tool treating Set-Cookie duplicates as singleton findings.**
Caught by frozen rule: H10 (line 178) — two `Set-Cookie` headers with `set-cookie` declared in `singleton_fields` must score 0 — and the worktree tool implements it (`NEVER_SINGLETON` skip in `evaluate()`). This cheat is closed on the audit side. Upstream residual gap [INFERENCE — verify against the integrated counter, whose frozen scope is "runs the audit tool as committed at the revision" (line 164)]: the counter never executes `scripts/response_snapshot.py`, so if the snapshot collapses duplicate header lines into `response.json`, real receipts silently under-report and `singleton_fields` can never fire on live data — H10 cannot see it because the counter hand-builds fixture manifests. The snapshot does record ordered name/value pairs plus `headerCount`, which makes the check easy: see T6.

## TIGHTENINGS:

- **T1 (closes Cheat 2).** Freeze for c61_header_cases.py, mirroring C1: the real manifest, the 12 capture receipts, and the audit tool bytes are all read via `git cat-file`/`git show` at `<rev>` into `--work`; the audit is executed from the extracted scratch copy with `GIT_*`/`PYTHONPATH` scrubbed and cwd inside `--work`; `--root` must be a repository toplevel. Reading any input from the lane worktree → counter exit 2.
- **T2 (closes Cheat 3 on the real manifest).** Extend R3's shape check: the 12 check ids are distinct and equal the frozen round-23 population ids; each check's `expect` block equals the policy pinned in `corpus/knowledge/response-header-expectations.md` (all four classes declared true for these 12 https surfaces; `set-cookie` absent from `singleton_fields`); `https` equals the receipt's recorded finalUrl scheme; `source` resolves to the receipt whose url/finalUrl matches the surface's round-23 URL. A vacuous or swapped real manifest then fails R3 and `met` cannot rest on it.
- **T3 (closes the Cheat-3 semantics ambiguity).** Add one frozen fixture case pinning the declared-false reading: `content_type_present: false` with a 2xx receipt lacking Content-Type → 0 findings (expected under flag-gated semantics, which the built tool implements). Today H16 cannot discriminate; w2 could mutate the tool to unconditional and still pass all 18.
- **T4 (closes Cheat 1 residuals).** Randomize fixture *bytes* per seed (decoy headers with random names/values, shuffled header order, random OWS) while preserving each case's rule-relevant features, so digest- or content-keyed sniffing fails on every seed; keep expected outcomes in counter memory only, never on disk under `--work`; define the manifest-sniffing composite control to key on manifest digest *and* ids so detection is content-complete.
- **T5 (closes Cheat 4's offline half).** In R3, recompute from committed bytes: receipt sha256 and bytes against the retained body (empty-body sha when `bodyFile` is null), `fetchedAt` on 2026-10-27, `userAgent` tagged `round61`, and first-parent ancestry of every receipt add-commit under the manifest commit. Require the audit run to leave a committed run receipt under `.ufo/waves/round-61/capture/` carrying the "Every receipt carries a first line `# receipt: <name>`" grammar, so fabrication-after-audit is visible in history. Live-fetch honesty stays with the sentinel — that delegation is sound.
- **T6 (closes Cheat 5's upstream gap).** Counter executes one snapshot run against a loopback fixture server (localhost, seeded port) that emits two `Set-Cookie` fields, and asserts the written `response.json` preserves both in order and `headerCount` agrees; or require `response_snapshot.py --selftest` to cover duplicate-header serialization and run it. Without this, H10's guarantee never reaches real receipts.

## VERDICT:

VERDICT: Impacted axis operability (C2); all five cheats target its counter, calibration/freshness untouched — 1 is caught by the frozen seeded-id rule plus composite control (with content-keying residual), 5 is caught on the audit side by H10 (with a snapshot-side residual), and 2, 3, 4 are fixable defects open today: adopt tightenings T1–T6 before the counter freezes or w2 will walk through the worktree-reading, vacuous-manifest, and receipt-fabrication holes.
