# Hreflang publication review: separate evidence gaps from relation defects

Author case response, after declaration2784870 and public reviewer oracle56028349.
These are invented saved-metadata cases. No website, browser, crawler or index was
observed. The oracle was visible; this is a manual application exercise, not a blind
exam, measured behavioral gain, or automated validator demonstration.

## Decision aid

Read the evidence boundary first: a complete applicable set can demonstrate absence;
a missing capture cannot. Keep separate notes for self-inclusion, target URL form,
each directed pair, and optional fallback. An incomplete cluster is not one boolean
failure: identify which pairs reciprocate. Only then propose specific edits or the
missing observation. Never substitute hostname similarity, file label, or a citation
id for the supplied metadata. This is author synthesis of S438's Guidelines for all
methods, HTML tags, HTTP Headers, and fallback guidance.

## Case dispositions

1. A/B reciprocal, self-inclusion present. Both complete sets contain A and B. Lack
of x-default does not require repair; a fallback may help unmatched-language visitors
if that is the publisher's purpose. Preserve these links and decide on fallback
separately. No claim that Google has processed either page follows.

2. Proven missing return on B, not an evidence gap. Complete B includes only itself,
so B-to-A is absent although A-to-B exists. Add en:A on B and inspect a new complete
saved set. Do not report observed index loss or reject A's self-link as the defect.

3. Unknown return, not proven missing. A's capture cannot tell us what B declares.
Obtain B's complete applicable metadata before deciding between cases1 and2; do not
prescribe an edit to unseen B or promise the pair is accepted.

4. Two reciprocal pairs A-B and A-C; no B-C pair. Self links are present. The global
all-versions recommendation is not fully followed, but the documented partial-set
allowance preserves the distinction between reciprocal and absent pairs. Propose
adding de:C on B and fr:B on C for completeness; do not demand rebuilding A or say
all relations are ignored. These are metadata properties, not engine observations.

5. A-D reciprocal with self-inclusion. D's example.net host is not grounds for
rejection. Keep the cross-domain relation; verify future source edits preserve both
ends instead of moving the Spanish page to example.com merely to satisfy a fabricated
same-host rule. Actual ownership, delivery and processing are outside the fixture.

6. A's /en and //example.com/fr are not fully transport-qualified URLs, even if a
browser could resolve them. Replace them with A and B respectively in A's source.
Then inspect the saved sets again. B's complete full URLs do not cure A's form defect;
syntactic URL correction alone is not a proof of crawl or index state.

7. A-B reciprocity exists: A points to B and B points to A. A's self-link is separately
missing. Add en:A to A's set. Calling this a missing B return would repair the wrong
page and erase the actual evidence. No exact engine handling is inferred from the
self-inclusion defect beyond what the documentation establishes.

8. Complete GET Link-header sets provide the supported alternate method. Both contain
self and return relations; absent HTML tags alone do not justify an edit. Keep one
maintained method rather than requiring duplicate HTML solely for this review. This
is not verification of actual served headers, PDF content, or processing.

## Admits, rejects and limits

Admit as a proposed useful manual aid: evidence completeness before absence claims;
pair-wise return evidence independent of self inclusion; optional fallback independent
of required-link repairs. Reject blanket clique/same-host/x-default rules, automatic
resolution of relative hrefs as documentary compliance, and compulsory HTML when
complete GET headers are supplied. Source claims remain scoped to Google's published
guidance, not all search engines or BCP47 validation.

The baseline's canonical and robots tools do not establish these relations; no tool
is repaired or claimed here. The aid reduces avoidable publisher edit mistakes by
naming the exact surface and missing observation. Outside review must decide whether
that is useful new calibration knowledge. Numeric calibration remains HOLD2.
