## Findings

### F1 — frozen grammar: RFC 822 / RFC 850 `unavailable_after` branches are unreachable; S452's canonical example is rejected (medium — contract defect, tool conformant)
Contract rule 1 splits every field value on ASCII `,` unconditionally, and both frozen non-ISO date shapes (rule 5) contain a literal `", "` — so no post-split segment can ever match `RFC822_RE`/`RFC850_RE`. Dead grammar, and a source contradiction:
- S452 canonical example `X-Robots-Tag: unavailable_after: Wed, 03 Dec 2025 13:09:53 GMT` (`w1/ScoutSources/mdn-x-robots-tag.txt:545`) → my run: `findings=[xrt_invalid_value, xrt_unknown_directive]`, exit 1 (receipt `ReviewC2/adv-results.txt` probe `a08-dates`, check `a08a-mdn-rfc822`). The comma inside the date splits the segment; `Wed` fails the value regex, the remainder parses as an unknown directive.
- RFC 850 `unavailable_after:Wednesday, 03-Dec-25 13:09:53 GMT` → same two findings (`a08c-rfc850`).
- S452 states "A date must be specified in a format such as RFC 822, RFC 850, or ISO 8601." (`mdn-x-robots-tag.txt:501`). S449's own example `unavailable_after: 25 Jun 2010 15:00:00 PST` (`google-robots-meta.txt:997`) additionally uses a timezone name the GMT-only frozen shape rejects.
- ISO branches behave per contract: date-only, space-form `2025-12-31 23:59`, and offset `+02:00` all accepted (`a08d/a08e/a08f`).
No frozen case is contradicted (c16/c17 pin ISO only), and the contract's assumptions disclose the shapes are frozen-case-pinned — but they do not disclose that two of the three pinned shapes can never match. **L1 ruling 2026-11-04: recorded as a stated limit** (grammar and tool unchanged post-measurement; ScribeRecord adds it to the lesson Limits/Mistakes and SCORECARD limits; a later round may amend with cases).
